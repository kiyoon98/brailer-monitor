1. 프로그램 개요

Brailer Monitor는 조업 영상에서 그물 또는 브레일러(brailer) 객체를 찾아 시간순으로 정리하고, 오탐을 후처리한 뒤 HTML·CSV·JSON 리포트로 내보내는 프로그램입니다. 모델 학습부터 운영 탐지까지 웹 화면 한 곳에서 수행하도록 구성되어 있습니다.

운영 중 서버 재시작 주의
탐지나 학습 중 서버를 종료하면 작업이 중단될 수 있습니다. 작업 중지 버튼을 먼저 누르고 상태가 종료됨으로 바뀐 뒤 재시작합니다. 작업 종료 코드 -15는 일반적으로 SIGTERM으로 종료되었다는 뜻이며, 사용자가 중지했거나 서버 재시작 과정에서 발생할 수 있습니다.

3.4 정상 동작 확인

  1. 웹 화면이 열리는지 확인합니다.
  2. 모델 라이브러리에서 모델 목록이 표시되는지 확인합니다.
  3. 짧은 영상 한 개로 탐지 시작 후 진행률과 현재 프레임이 움직이는지 확인합니다.
  4. 탐지 완료 후 모델 선택 변경과 결과 초기화 버튼이 정상 동작하는지 확인합니다.

4. CVAT 주석 데이터 준비

4.1 CVAT에서 프로젝트 만들기

  1. CVAT에서 Task를 만들고 원본 영상을 업로드합니다.
  2. Label을 생성합니다. CVAT의 label 하나가 YOLO의 class 하나에 해당합니다.
  3. 현재 운영 대상이라면 label 이름을 brailer로 통일하는 것을 권장합니다.
  4. Detection 모델은 Rectangle(Box), Segmentation 모델은 Polygon으로 객체를 표시합니다.
  5. 작업 완료 후 빈 label, 잘못된 클래스, 화면 밖 좌표, 중복 도형을 검수합니다.

4.2 Box와 Polygon의 차이

주석 종류학습 작업장점주의점
Rectangle / BoxYOLO detection주석이 빠르고 bbox 탐지에 적합객체 내부의 정확한 모양은 학습하지 않음
PolygonYOLO segmentation객체 외곽 마스크와 면적·형태를 사용할 수 있음주석 시간이 길고, 외곽점 품질이 중요

Polygon 점이 많다고 무조건 정확해지는 것은 아닙니다. 실루엣의 굴곡을 설명할 만큼은 필요하지만, 불필요하게 촘촘하거나 흔들리는 점은 label noise가 됩니다. 객체의 실제 외곽을 일관되게 따라가고, 프레임마다 비슷한 기준으로 점을 찍는 것이 더 중요합니다.

4.3 Label 품질 원칙

  • 같은 물체를 brailer, brailers, net처럼 여러 이름으로 나누지 않습니다.
  • 객체가 보이지 않거나 판단할 수 없는 프레임에는 억지로 주석하지 않습니다.
  • 빈 label 정의는 삭제합니다. 좌표 없는 label 정의만 남는 것은 학습 정보가 아닙니다.
  • 부분 가림, 야간, 날씨, 카메라별 샘플을 train/val에 고르게 포함합니다.
  • 연속 프레임만 과도하게 넣지 말고 실제 운용 조건의 다양성을 확보합니다.

4.4 CVAT Export

권장 형식은 CVAT for video 1.1입니다. ZIP 안에 이미지가 없으면 원본 영상을 Brailer Monitor Import 시 함께 지정해야 합니다. annotations.xml만 Export해도 사용할 수 있습니다.

CVAT에서 “YOLO” 형식으로 Export한 데이터셋도 표준 YOLO 디렉터리로 사용할 수는 있지만, 현재 웹 Import는 CVAT 1.1 ZIP/XML을 기준으로 프레임 추출, 메타데이터, 모델 프리뷰를 함께 구성합니다. 따라서 운영 절차에서는 CVAT 1.1 Import를 권장합니다.

5.3 train과 val

train은 모델의 가중치를 업데이트하는 데이터이고, val은 학습 중 보지 않은 데이터에 대해 성능을 확인하는 데이터입니다. val 결과가 좋지 않다면 epoch만 늘리기보다 데이터 분포, 주석 오류, 카메라·시간대 다양성을 먼저 점검합니다.

5.4 CLI Import

python -m brailer_monitor import-cvat annotations.xml \
  --video source.mp4 \
  --dataset-root data/dataset \
  --val-ratio 0.2 \
  --seed 42

기본 Import는 기존 데이터셋을 정리한 뒤 새 데이터를 구성합니다. 기존 데이터와 합쳐야 하는 특수한 경우에만 --no-clean을 사용하고, 동일 파일명과 클래스 번호 충돌을 직접 점검합니다.

6. YOLO 모델 학습과 모델 라이브러리

6.1 웹 학습 절차

  1. Import된 프레임과 클래스가 정상인지 확인합니다.
  2. YOLO 학습에서 Epochs, Batch, 학습 크기를 설정합니다.
  3. GPU를 사용할 경우 device가 올바른지 확인하고 학습 시작을 누릅니다.
  4. epoch와 batch 진행률을 확인합니다. 학습 완료 전 서버를 재시작하지 않습니다.
  5. 완료된 best.pt는 모델 라이브러리에 자동 등록됩니다.
  6. 모델 프레임과 실제 영상 테스트로 품질을 확인합니다.

7. 외부에서 학습한 YOLO 모델 넣기

7.1 지원 대상

Ultralytics YOLO가 읽을 수 있는 .pt 가중치를 모델 라이브러리에 등록할 수 있습니다. 외부 모델은 현재 웹 화면의 파일 업로드가 아니라 ModelLibrary.register()를 사용해 등록합니다.

7.2 등록 전 확인

  • 현재 설치된 Ultralytics 버전에서 YOLO("/path/to/best.pt")가 열리는지 확인합니다.
  • 모델 task가 detect 또는 segment인지 확인합니다.
  • 클래스 이름에 brailer가 있는지 확인합니다.
  • 외부 파일을 원본 위치에서 바로 참조하지 않고 라이브러리로 복사해 보관합니다.

7.3 등록 명령 예시

cd /home/koast/Documents/brailer-monitor
source .venv/bin/activate

python - <<'PY'
from pathlib import Path
from ultralytics import YOLO
from brailer_monitor.model_library import ModelLibrary

weights = Path("/path/to/best.pt").resolve()
yolo = YOLO(str(weights))
task = str(getattr(yolo, "task", None) or "detect")
names = getattr(yolo, "names", {})
class_names = (
    [str(names[key]) for key in sorted(names)]
    if isinstance(names, dict)
    else [str(name) for name in names]
)

record = ModelLibrary(Path("models/library")).register(
    weights,
    task_type="segment" if task == "segment" else "detect",
    name="external-model-name",
    class_names=class_names,
    source="external",
)
print(record.id, record.weights_path)
PY

등록 후 웹 화면에서 모델 새로고침을 누르고 모델과 클래스 이름을 확인합니다.

클래스 이름 변경 주의
meta.json의 표시 문자열만 바꾸는 것은 모델이 학습한 클래스 의미를 바꾸지 않습니다. 가능한 한 CVAT 단계에서 brailer로 통일해 다시 학습하십시오. 현재 앙상블에서는 brailer와 brailers를 같은 클래스로 정규화하지만, 다른 클래스 이름은 별개 클래스로 처리됩니다.

7.4 외부 모델 프리뷰

외부 모델은 Brailer Monitor에서 학습한 데이터셋과 연결 정보가 없으므로 previews/가 비어 있을 수 있습니다. 이는 모델 가중치의 이상을 뜻하지 않습니다. 모델의 출처, 학습 데이터, 클래스, 성능 지표는 별도 기록으로 남기는 것을 권장합니다.

8. 멀티모델 앙상블

8.1 사용하는 이유

카메라, 선박, 날씨, 시간대가 다른 데이터로 학습한 여러 모델을 함께 사용하면 한 모델이 놓친 객체를 다른 모델이 찾을 수 있습니다. 반대로 모든 모델이 같은 편향을 갖고 있으면 오탐도 함께 늘 수 있으므로 모델 조합은 실제 검증 영상으로 평가해야 합니다.

8.2 현재 앙상블 처리 방식

  1. “탐지”로 선택된 각 모델이 같은 프레임을 독립적으로 추론합니다.
  2. 클래스 이름을 정규화합니다. brailer와 brailers는 같은 클래스로 봅니다.
  3. 같은 클래스의 bbox가 IoU 기준으로 충분히 겹치거나 한 bbox가 다른 bbox 안에 포함되면 같은 객체 후보로 묶습니다.
  4. 겹친 후보 중 대표 bbox/mask는 더 큰 bbox 후보를 기준으로 남깁니다.
  5. Confidence는 후보 중 가장 높은 값을 사용합니다.
  6. 대표 모델과 기여한 모델 목록을 결과 label과 리포트 메타데이터에 기록합니다.

8.3 IoU란

IoU(Intersection over Union)는 두 bbox가 겹치는 면적을 두 bbox의 합집합 면적으로 나눈 값입니다. 0이면 전혀 겹치지 않고 1이면 완전히 같습니다. 현재 앙상블의 기본 겹침 기준은 약 0.5입니다. IoU 병합은 클래스별로 수행되므로 서로 다른 클래스의 객체는 위치가 겹쳐도 자동으로 하나가 되지 않습니다.

8.4 모델 선택 지침

상황권장 구성주의점
단일 카메라·환경해당 카메라 데이터로 검증된 모델 1~2개불필요한 모델은 속도만 낮출 수 있음
여러 선박·시간대환경별로 강점이 다른 모델 여러 개오탐이 많은 모델은 제외
실시간 스트림지연 목표에 맞춰 모델 수 최소화모델 수에 비례해 추론 시간과 GPU 메모리 증가
정밀 사후 분석검증된 모든 관련 모델 + SAM처리 시간이 길어짐
모델 수를 2배로 늘리면 실제 총 소요시간도 대체로 증가합니다. 프레임 간격을 키우거나 SAM을 끄는 방식으로 속도를 조절할 수 있지만, 짧게 나타나는 객체나 마스크 정밀도가 떨어질 수 있습니다.

10. 탐지 옵션과 진행 모니터링

10.1 공통 탐지 옵션

옵션현재 기본값설명
프레임 간격5모든 프레임이 아니라 5번째 프레임마다 추론합니다. 값이 작을수록 놓침은 줄지만 느려집니다.
Confidence0.5모델 예측을 결과로 인정하는 최소 신뢰도입니다. 낮추면 recall과 오탐이 함께 증가할 수 있습니다.
추론 크기416YOLO 입력을 letterbox resize하는 크기입니다. 원본 영상 출력 크기를 바꾸는 설정이 아닙니다.
SAM 정밀 마스크사용YOLO 결과를 바탕으로 SAM 마스크를 추가 계산합니다. YOLO mask는 cyan, SAM mask는 yellow로 표시합니다.
어두운 영상 건너뛰기사용파일·저장소 영상의 대표 샘플을 사전 검사해 전체가 명확히 어두우면 YOLO 처리를 생략합니다.
바다 영역 분석사용 안 함선박 조우·이탈 판단을 위해 바다 비율과 상태를 계산합니다.
바다 영역만 분석사용 안 함YOLO 객체 탐지와 SAM을 실행하지 않고 바다 영역만 계산합니다.
바다 분석 간격5초0은 처리하는 모든 프레임, 최대 300초(5분)까지 지정할 수 있습니다.

10.2 탐지 영역(ROI)

현재 기본값은 상 0%, 하 0%, 좌 15%, 우 15%입니다. 즉 전체 높이는 사용하고, 수평 방향으로는 화면의 15~85% 안에 있는 탐지만 결과에 포함합니다. 카메라별로 그물 작업 위치가 다르면 먼저 짧은 범위에서 ROI를 조정합니다.

ROI는 오탐이 자주 발생하는 가장자리 영역을 본탐지 단계에서 제외하기 위한 설정입니다. 리포트에는 실제 적용된 ROI가 x 15-85%, y 0-100% 같은 형식으로 기록됩니다.

10.3 바다 영역 분석

Hybrid 엔진은 semantic segmentation과 OpenCV 기반 형태·시간 정보를 조합합니다. 바다 비율뿐 아니라 calibrating, open_sea, encounter, departure, unknown 상태를 기록할 수 있습니다. GPU 객체 탐지와 충돌을 줄이기 위해 semantic 모델은 기본적으로 CPU에서 실행합니다.

PyTorch 또는 semantic 모델을 사용할 수 없으면 legacy 분석으로 내려갈 수 있으며, 색·텍스처 의존도가 높아져 날씨와 시간대 변화에 대한 정확도가 낮아질 수 있습니다.

10.4 진행 상태 확인

12. 후처리

12.1 기본 원칙

후처리는 한 시간대 또는 반나절 동안 반복되는 실제 전재 작업의 탐지들이 대체로 비슷한 위치·크기·형태를 가진다는 가정으로 오탐을 줄입니다. 모든 후처리 옵션은 현재 UI에서 기본 선택되어 있습니다.

후처리는 현재 열려 있는 타임라인에서 탐지 프레임을 실제로 제거합니다. 먼저 현재 결과 저장으로 원본 결과를 별도 이름으로 보관한 뒤 후처리를 적용하십시오. 같은 저장 결과에 반복 적용하면 이미 제거된 결과를 자동 복원하지 못합니다.

12.2 병합 조건

조건현재 기준효과
연속 구간 병합같은 클래스의 구간 사이가 8초 이내중간 프레임에서 잠시 놓친 탐지를 하나의 작업 구간으로 표시합니다. 탐지 프레임을 새로 만들지는 않습니다.

12.3 제거 조건

조건현재 핵심 기준설명
위치 이상 동일 영상·클래스 또는 작업 시간대의 중심 위치 분포에서 robust outlier 중앙값 거리와 MAD, bbox 대각선 크기를 함께 사용합니다. 작업 단위는 최대 12시간 범위로 보며, 반복되는 정상 위치는 보호하되 하단 ROI 경계·깊은 하단·엄격한 작업 위치 이상은 보호하지 않을 수 있습니다.
크기 이상 동일 영상·클래스의 면적 중앙값 대비 50% 이하 또는 200% 이상 같은 영상의 일반 탐지보다 지나치게 작거나 큰 객체를 제거 후보로 만듭니다. 비교 대상이 3개 미만이면 적용하지 않습니다.
하단 대형 바다 영역 작업 내 10개 이상, 면적 4배 초과, bbox 하단 98% 이상, 중심 y 65% 이상 화면 아래 바다나 선체를 매우 큰 객체로 잘못 찾은 결과를 제거합니다.
세로로 긴 빈 그물 bbox의 width / height < 0.5 폭이 높이의 절반보다 작은 세로형 bbox를 제거합니다.
같은 위치 정지 3초 이상 또는 6프레임 이상, 중심 이동이 작음 고정 구조물이나 배경을 반복 탐지한 결과를 제거합니다. 3프레임·0.5초 이상에서 중심 2px 이하, 크기 변화 8% 이하인 엄격 조건도 있습니다. 여러 영상에 걸친 장기 정지 오탐도 별도로 검사합니다.
시간적으로 고립 앞뒤 10초에 비슷한 크기의 탐지가 없음, 최대 3프레임·1초 이하 burst 짧고 주변 근거가 없는 탐지를 제거합니다. 8초 병합으로 한 구간이 된 탐지와 같은 작업 12시간 내 반복된 유사 탐지는 보호합니다. 현재 이 조건은 중심거리 차이를 요구하지 않습니다.
색상 이상 / 균일한 밝은색 평균 gray ≥170, 중앙값 ≥190, 밝고 균일한 픽셀 ≥72%, Lab 거리 ≤35 밝고 균일한 선체·구조물 오탐을 제거합니다. 그룹 내 5개 이상이면 평균 BGR 색이 크게 다르고 saturation이 높은 상대 색상 이상도 검사합니다.

12.4 반복 작업 보호

같은 source 계열과 클래스에서 최대 12시간 안에 크기와 형태가 유사하게 반복된 탐지는 정상 작업일 가능성이 높다고 보고 위치·크기·시간 고립·일반 색상 이상 제거에서 보호할 수 있습니다. 단, 다음과 같이 명백한 배경 오탐 성격이 강한 조건은 보호보다 제거가 우선할 수 있습니다.

  • 균일한 밝은색 조건
  • 하단의 지나치게 큰 바다 영역
  • 하단 ROI 경계 또는 깊은 하단에서 반복되는 강한 위치 이상
  • 오랜 시간 여러 영상에서 거의 같은 위치와 크기로 고정된 배경 탐지

12.5 적용 절차

  1. 후처리 전 현재 결과를 저장합니다. 예: raw_20260314.
  2. 원하는 조건을 선택합니다. 처음에는 기본 전체 선택을 사용합니다.
  3. 후처리 적용을 누릅니다.
  4. 메시지에서 병합 구간 수, 제거 탐지 수, 제거 프레임 수를 확인합니다.
  5. 타임라인의 의심 구간과 정상 구간을 모두 샘플 검토합니다.
  6. 문제가 있으면 원본 저장 결과를 다시 불러와 조건을 줄여 재시도합니다.

  1. 탐지가 끝나면 현재 결과 저장으로 이름을 지정해 저장합니다.

15.1 주요 데이터 경로

경로내용삭제 주의

15.2 백업 권장 단위

  • 검증 완료 모델: 모델 디렉터리 전체(weights.pt와 meta.json 포함)
  • 학습 재현 데이터: CVAT 원본 Export, 원본 영상, dataset.yaml
  • 운영 결과: 후처리 전·후 저장 결과, HTML·CSV·JSON 세 파일
  • 설정: config/와 사용한 소스·모델·confidence·ROI 기록

15.3 자주 발생하는 문제

증상확인 사항과 조치
첫 번째 영상 이후 진행되지 않음 현재 영상의 worker.log, progress.json, 작업자 프로세스를 확인합니다. 손상 영상, 네트워크 다운로드 대기, GPU 오류가 원인일 수 있습니다.
진행 scale이 움직이지 않음 현재 작업 상태와 작업자 생존 여부를 확인합니다. 첫 모델 로딩, SAM 초기화, 저장소 다운로드 중에는 프레임 진행 전 대기할 수 있습니다.
학습이 epoch 1에서 멈춘 것처럼 보임 batch 진행률, GPU 메모리, 데이터 수, dataloader 로그를 확인합니다. 첫 epoch의 모델 초기화와 캐시 준비가 오래 걸릴 수 있습니다.
CUDA illegal memory access 해당 작업을 중지하고 worker 프로세스를 종료한 뒤 새 작업으로 실행합니다. 오류가 난 CUDA context에서는 empty_cache()만으로 복구되지 않습니다. 바다 semantic 분석은 CPU 사용을 권장합니다.
Segmentation shape 오류 모델 task와 가중치가 호환되는지, 파일이 손상되지 않았는지 확인합니다. 현재 detector는 일부 segmentation postprocess 오류에서 bbox detect fallback을 시도하지만 mask는 없을 수 있습니다.
스트림 영상이 gray/spinner 상태 HLS manifest와 segment 요청이 브라우저에서 계속 성공하는지 확인합니다. 소스 reset 시 재연결을 기다리고, 장시간 복구되지 않으면 스트림과 탐지를 중지 후 다시 시작합니다.
모델이 새로고침 후에만 보임 등록된 meta.json과 가중치 경로를 확인하고 모델 새로고침을 수행합니다. 전체 리로드에서도 사라지면 등록 경로와 읽기 권한을 확인합니다.
리포트가 화면 결과와 다름 리포트 생성 전 원하는 저장 결과를 실제로 불러왔는지, 후처리 적용 후 저장/로드 상태가 일치하는지 확인합니다.
색상 후처리가 동작하지 않음 해당 작업의 detect_jobs/<job-id>/video.mp4가 남아 있어야 원본 bbox crop의 색을 다시 계산할 수 있습니다.

15.4 속도 개선 우선순위

  1. 탐지에 필요 없는 모델을 선택 해제합니다.
  2. 짧은 객체를 놓치지 않는 범위에서 frame stride를 늘립니다.
  3. 정밀 mask가 필요 없는 분석에서는 SAM을 끕니다.
  4. 작은 객체 성능이 허용되면 imgsz를 낮춥니다.
  5. 바다 영역 분석 간격을 늘리거나 사용하지 않습니다.
  6. 저장소 범위를 나누어 실행하고 불필요한 야간 영상은 dark skip으로 제외합니다.

부록 A. CLI 빠른 참조

A.1 웹 서버

python -m brailer_monitor web --host 0.0.0.0 --port 8080

A.2 CVAT Import

python -m brailer_monitor import-cvat annotations.xml \
  --video source.mp4 \
  --dataset-root data/dataset

A.3 학습

python -m brailer_monitor train \
  --dataset config/dataset.yaml \
  --epochs 50 --batch 4 --imgsz 416 --device 0

A.4 단일 영상 탐지

python -m brailer_monitor detect-video input.mp4 \
  --model models/library/MODEL_ID/weights.pt \
  --out output/detect \
  --frame-stride 5 \
  --confidence 0.5 \
  --roi-top 0 --roi-right 0.15 --roi-bottom 0 --roi-left 0.15

A.5 바다 영역만 분석: 단일 파일 탐지 명령

python -m brailer_monitor detect-video input.mp4 \
  --sea-only \
  --sea-ratio \
  --sea-analysis-interval-sec 5 \
  --sea-device cpu

A.6 바다 영역: 저장소

python -m brailer_monitor sea-area storage \
  --start 2026-01-28T03 \
  --end 2026-01-28T04 \
  --media lake_win \
  --year-folder 2026_decrypted \
  --vessel JJR-102283 \
  --camera-stream stream04 \
  --minute-offsets 0,1,2,3,4 \
  --second-suffixes 16 \
  --sea-engine hybrid \
  --device cpu \
  --frame-stride 75

sea-area 명령의 간격은 프레임 수(--frame-stride)입니다. 예를 들어 15fps에서 5초 간격은 75프레임입니다. 웹과 detect-video의 --sea-analysis-interval-sec는 초 단위입니다.

A.7 바다 영역: 실시간 스트림

python -m brailer_monitor sea-area stream \
  --url http://127.0.0.1:8081/live_04.m3u8 \
  --duration-sec 600 \
  --frame-stride 75 \
  --sea-engine hybrid \
  --device cpu \
  --jsonl-out output/sea-area.jsonl

부록 C. 운영 체크리스트

C.1 모델 학습 전

  • ☐ CVAT label 이름이 brailer로 통일되어 있다.
  • ☐ Box 또는 polygon 유형이 원하는 YOLO task와 맞다.
  • ☐ 빈 label, 중복 도형, 잘못된 프레임 좌표를 제거했다.
  • ☐ Import된 train/val 프레임과 class 수를 확인했다.
  • ☐ GPU 메모리에 맞는 batch와 imgsz를 정했다.

C.2 탐지 시작 전

  • ☐ 사용할 모델의 “탐지” 체크박스를 확인했다.
  • ☐ 소스와 기간 또는 스트림 URL이 맞다.
  • ☐ Lake 저장소는 “영상 확인”을 먼저 수행했다.
  • ☐ Confidence, frame stride, imgsz, ROI를 기록했다.
  • ☐ SAM, dark skip, sea analysis 사용 여부를 확인했다.
  • ☐ 기존 현재 결과를 저장하거나 초기화했다.

C.3 탐지 완료 후

  • ☐ 처리 영상 수와 건너뛴 영상 수를 확인했다.
  • ☐ 후처리 전 결과를 별도 이름으로 저장했다.
  • ☐ 후처리 제거·보호·병합 통계를 기록했다.
  • ☐ 정상/오탐 구간을 표본 검토했다.
  • ☐ 현재 열려 있는 결과와 리포트 대상이 일치한다.
  • ☐ HTML·CSV·JSON 리포트가 모두 생성되고 열리는지 확인했다.
